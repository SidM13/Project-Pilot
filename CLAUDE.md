# ProjectPilot AI — project conventions

@AGENTS.md

Decision-intelligence workspace for PMs/ops leads at small consulting and professional-services firms.
Product plan and stage status: `docs/architecture.md`. Calculation rules: `docs/calculations.md`.

## Stack
Next.js 16 App Router (Cache Components on), TypeScript strict, Tailwind v4, shadcn/ui (radix), Supabase (Postgres + Auth + RLS), Zod, Vitest. npm. Gemini (REST, no SDK) behind `src/lib/ai` (provider abstraction in `types.ts`, server-only config in `index.ts`). Never add the Claude/Anthropic API to the app.

## Non-negotiable rules
- **Numbers come from the engine, never from AI.** `src/lib/engine/*` is pure TypeScript: no I/O, no `Date.now()`. "Today" is only ever `getReferenceDate(workspace)` passed in as `referenceDate`.
- **Three layers stay visibly separate in the UI:** Facts (DB records) → Calculated findings (engine) → AI text (labelled "AI draft").
- AI calls go through `runGrounded()` (`src/lib/ai/service.ts`): cache → hourly limit → model → Zod → `findUngroundedFigures` → cache. The model receives only engine-built context (`lib/ai/grounding.ts`, `lib/briefs/facts.ts`) and has no write path. Bump `PROMPT_VERSION` when prompts or schemas change.
- The capacity forecast (`engine/forecast.ts`) is the single source of finish dates; findings and (Stage 3) simulations must use it rather than ad-hoc date math.
- Every new rule or threshold goes in `docs/calculations.md` and gets a test in `src/lib/engine/__tests__/`.
- Simulations (`engine/simulate.ts`) run on a `structuredClone` of the snapshot; the only write path is `applySimulation` in `src/actions/simulations.ts`, which re-validates and re-simulates server-side after explicit approval.
- Deferred tasks (`deferred_at`) are excluded in `analyzeWorkspace`; never delete tasks for scope reduction.
- After writes in the same request, load data with `loadWorkspaceSnapshot` (uncached), not the cached `getWorkspaceSnapshot`.
- No dead UI: a nav item, button or chart ships only when it works. Hide unfinished sections (`src/components/layout/nav-items.ts`).

## Build targets
- Default build: the full-stack app (Vercel/Node).
- `npm run build:pages` (`NEXT_BUILD_TARGET=pages`): static GitHub Pages demo under `/Project-Pilot/`. Only `*.static.tsx` files are routes. `next.config.ts` aliases server-only modules to `src/static/*` and `@/actions/*` to browser copies generated by `scripts/gen-static-actions.mjs` (gitignored). Server pages are split into `screen.tsx` (`load…` + `…View`) so both builds share loaders and views — keep that split when adding pages, and add a `page.static.tsx`.
- Links to projects/briefs must use `projectHref` / `briefHref` (`src/lib/routes.ts`); the static build uses query URLs.
- Import aliased modules by their `@/` path (aliases do not apply to relative imports).
- `server-only` stays only on modules that read secrets or request state (`lib/supabase/server`, `lib/ai/index`, `lib/ai/service`, `lib/data/workspace`).
- Run `npm run security:scan` before pushing; CI runs it plus the build-output scan.

## Data modes
- `PROJECTPILOT_DATA_MODE=demo` (default): `createClient()` returns the in-memory demo client (`src/lib/demo/client.ts`). If you use a new query-builder method or table behaviour in app code, add it to the demo client/store and `src/lib/demo/__tests__`.
- Demo data has one source: `src/lib/demo/dataset.ts` (engine tests use it with readable ids; the store with stable UUIDs). `0002_demo_seed.sql` mirrors it for database mode.

## Data & security
- Tenancy = workspace. Every table has `workspace_id`; child rows use composite FKs `(parent_id, workspace_id)` so cross-workspace links are impossible.
- RLS on every table via `is_member(ws)` / `has_role(ws, roles)`. The app only uses the anon key + user session (`src/lib/supabase/server.ts`). The service-role key is used **only** by `scripts/*.mjs`.
- Reads: `src/lib/data/*` (`getWorkspaceSnapshot`, `getAnalysis`, `getProjectView`), all wrapped in React `cache`. Postgres numerics are converted to numbers there.
- Writes: server actions in `src/actions/*` → Zod schema from `src/lib/validation.ts` → Supabase → `logActivity()` → `refresh()`. Return `ActionResult`; map errors with `fail()`.
- Migrations live in `supabase/migrations` (append new numbered files; never edit applied ones once shared).

## Next.js 16 specifics
- `proxy.ts` (not middleware) refreshes the session and gates routes.
- Cache Components: anything reading cookies/params/pathname must render inside `<Suspense>` (route `loading.tsx` counts). Build fails otherwise — run `npm run build` to check.
- `params`/`searchParams` are promises; use the global `PageProps<"/route">` / `LayoutProps<"/route">` types (`npm run typecheck` regenerates them).

## Design system
- Tokens in `src/app/globals.css`: canvas `#F7F6F3`, surface white, warm light sidebar (`--nav`), single accent `#2457C5`, semantic critical/warning/healthy (+ `-soft` backgrounds). Light theme only.
- Navigation is four items (`nav-items.ts`): Home, Projects, AI Copilot, Reports. Project tabs: Overview, Tasks, Timeline, Budget, Team. Progressive disclosure: most important first, details behind `<details>` or a view switch.
- Inter (UI, `tabular` utility for figures), Source Serif 4 (`font-serif`, page titles only), IBM Plex Mono (dates/ids, sparingly).
- Building blocks in `src/components/system`: `Panel`, `PageHeader`, `MetricStrip`, `Pill`/`SeverityPill`/`HealthPill`/`TaskStatusPill`, `EvidenceList`, `EmptyState`, `SourceLabel`, `Field`, `NativeSelect`, `useActionForm`.
- 6px control radius, 8px panels, 1px borders, no card shadows, no gradients/glow/emoji. Icons only where they carry meaning.

## Demo
- Demo workspace (`is_demo`) is seeded by `seed_demo_workspace()` in `supabase/migrations/0002_demo_seed.sql`, dates relative to `reference_date` (default 2026-11-16, Monday).
- `src/lib/engine/__tests__/fixtures.ts → demoSnapshot()` mirrors that seed; `demo-scenario.test.ts` asserts the narrative (ERP blocker ranked first, Website at risk via Maya's overload, Ops healthy with thin headroom). Change both together.
- Website Migration is the Agile sample (four sprints, Sprint 3 overcommitted vs velocity); ERP and Operations are Waterfall with baselines. Migration 0007 wraps the 0002 seed to add these; keep `dataset.ts` and 0007 in sync.
